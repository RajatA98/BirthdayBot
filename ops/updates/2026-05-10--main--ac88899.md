## Summary

Fix two CSS bugs on the Preview step. Diagnosed via MDN +
CSS-Tricks + Defensive CSS research — these are textbook "use the
defensive pattern" cases.

### 1. Postcard rendering at 0 size (invisible)

Symptom: on Step 5, the left column was empty cream space; no
photo, no spinner overlay, no postcard background. The earlier
fix (c3ef602) added `max-height: min(70vh, 640px)` to
`.bb-postcard.is-preview` plus `width: auto` and `aspect-ratio: 4/5`
inherited from `.bb-postcard`.

Why it broke: block elements default to `min-height: auto`, which
for a container whose only children are absolutely-positioned
(the `.bb-photo-fill` overlay or `.bb-rendering` div) effectively
resolves to 0. With `aspect-ratio: 4/5` then deriving width from
that 0 height, the postcard collapsed to an invisible zero-by-zero
box. The `max-height` and the aspect-ratio rule never had a chance.

Fix: add `min-height: 0` to `.bb-postcard.is-preview`. That
overrides the default and lets `max-height` actually clamp. With
height bound, `aspect-ratio: 4/5` scales width down to maintain
4:5. `width: auto` + `max-width: 100%` + the inherited
`overflow: hidden` on `.bb-postcard` keep children clipped within.

### 2. Horizontal page scroll on narrow viewports

Symptom: a horizontal scrollbar appeared at the bottom of the
viewport between ~900-1200 px wide; the right sidebar bled past
the right edge.

Why: `.bb-step-panel` had `max-width: 1100px; margin: 0 auto`. On a
viewport narrower than 1100 px, max-width doesn't force any width
— it only caps. The panel inherited the default `min-width: auto`
from being a flex/grid child of `.bb-wizard-body { overflow: auto }`,
so it demanded its intrinsic content width and the body grew a
horizontal scrollbar.

Fix: add the standard defensive-CSS triple to `.bb-step-panel`:
- `width: 100%` so the panel actually fills its parent up to the
  cap.
- `min-width: 0` so it can shrink below intrinsic content width.
- `box-sizing: border-box` so the 40 px horizontal padding is
  folded into the 100% width calc rather than added on top.

Combined with the existing `.bb-preview-side { min-width: 0 }` and
`grid-template-columns: minmax(0, 1fr) minmax(260px, 340px)`, the
preview layout now shrinks gracefully from 1100 px down through
the 880 px breakpoint where it stacks to single-column.

## Blockers Or Risks

- Both fixes are CSS Grid Level 1 / aspect-ratio Level 1, shipped
  in evergreen browsers since 2021. No quirks expected.
- The `:has()` selector on `.bb-step-panel:has(.bb-preview-layout)`
  still requires Chrome 105+ / Safari 15.4+ / Firefox 121+ — same
  ground as before; older browsers fall back to the 720 px panel
  with the same min-width: 0 rule, so the regression is only
  cosmetic (slightly cramped sidebar) not broken.
