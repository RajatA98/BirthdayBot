# Ops Update

- Date: 2026-05-10
- Branch: main
- Commit: c57ccce

## Summary

Product pivot: BirthdayBot + HolidayBot reframed as a single
**photo-to-video-message app**. Occasion is no longer a routing
concept — it's an **inline filter** on the Prompt step (Just-a-message
/ Birthday / Mother's Day). New default is "Just a message" (general),
which has no holiday seasoning at all and lets the user's prompt drive
everything.

What landed:
- `Occasion` union grows by `"general"` and the default-when-absent
  flips from `"birthday"` → `"general"` everywhere (`getOccasionConfig`,
  `occasionFromDraft`).
- `lib/occasions.ts` adds a `general` config (empty greeting, neutral
  scene-opening line, generic prompt suggestions). Replaces the
  exported `holidayRail` with a compact `occasionPickerOptions` list
  for the dropdown.
- `lib/agent-plan.ts`, `lib/tools/plan-birthday-video.ts`,
  `lib/tools/build-video-input.ts`, `lib/tools/create-voice-over.ts`
  all branch on `isGeneral` so the generic path skips "Happy ___"
  greetings, party-trope celebration lines, and Mother's-Day-style
  negative-prompt extras. Birthday + Mother's Day paths are unchanged.
- `app/page.tsx`: new `<select>` occasion picker on Step 3. The
  dashboard's "Try our other cards" rail (`HolidayRail`) is deleted.
  `Friend` carries an `occasion?` field; `blankFriend()` defaults it
  to `"general"`. Both `buildSimpleDraftRequest` and `buildDraftRequest`
  thread occasion + adjust their fallback prompts.
- `app/mothers-day/` route deleted. `/mothers-day` now 404s.
- ~380 lines of orphaned `.md-*` and `.bb-holiday-*` CSS removed; a
  small `.bb-occasion-picker` block added.
- 4 test files updated to pin `occasion: "birthday"` on their shared
  makeDraft helpers (their assertions exercise the birthday flow). 2
  new tests assert the general-occasion contract: no birthday/Mother's
  Day framing in the fal prompt, no party-trope negative-prompt extras
  in the fal input. **54 tests green.**

## Blockers Or Risks

- Anyone who bookmarked `/mothers-day` will hit a 404. The dashboard
  already exposes Mother's Day via the picker so the flow is intact —
  just the URL changes. If we care about that link surviving, add a
  `redirects` entry in `next.config.ts` later.
- BirthdayBot brand strings (sidebar, logo, hero copy) are unchanged.
  Pivot the copy when a final product name is settled. Out of scope
  for this commit.
- Mother's Day sparkle-pop-out overlay treatment from commit `ad3fb29`
  was scoped to the deleted `/mothers-day` page. The unified flow's
  result postcard currently has the simpler birthday-style overlay.
  Porting the sparkle treatment into the dashboard's `ResultVideo`
  (gated on `occasion === "mothers-day"`) is a follow-up.

## Next Context

Adding more presets is now a 2-line change:
1. Add the id to `Occasion` in `lib/types.ts`.
2. Register the config in `occasionConfigs` (greeting, scene-opening
   line, plan/caption seasoning, optional negative-prompt extras,
   prompt suggestions). The dropdown auto-renders new entries via
   `occasionPickerOptions` — add the new id there too.

Backend assumption to remember: when occasion is absent on a payload,
the default is now `"general"` (was `"birthday"`). Anything that
existed before this commit and gets re-run will resolve to general
unless it set `occasion` explicitly. Tests that exercise the birthday
flow already do this; client code in `app/page.tsx` always sets it.

If we ever want `/mothers-day` (or `/birthday`) to deep-link into the
picker with that preset pre-selected, add a `useSearchParams` hook in
`app/page.tsx` and seed `blankFriend().occasion` from the query param.
