## Summary

The sparkly Mother's Day overlay now pops out toward the end of the
playback instead of sitting there for the whole video.

Behavior:
- During playback the overlay is muted (`opacity:0`, scale 0.6) so
  the cinematic scene reads clean.
- 2.6s before video end, an `onTimeUpdate` handler in `StepBrief`
  flips `isPopped` → `.md-overlay-popped` is applied.
- That triggers `md-pop-in` (700ms cubic-bezier scale-bounce, peaks
  at 1.08 with a brightness spike) + `md-sparkle-burst` on every
  star (scale 0.2 → 1.6 → 1 + 360° rotation, staggered 0–300ms) +
  two confetti-burst sparkles (`md-sparkle-c1/c2`) above/below the
  panel.
- Seeking back resets the trigger so the pop fires again on replay.
- Before generation (static photo preview) the overlay stays
  visible — the timed treatment is gated on `generation.videoUrl`.

## Blockers Or Risks

- The 2.6s lead time is tuned for ~10-15s videos. If we ever ship
  much shorter (< 4s) clips, the trigger window could overlap with
  the start. A guard like `if (video.duration < 5) skip-timed-mode`
  would handle that — not needed today, our shortest path is 10s.

## Next Context

The downloaded MP4 still does NOT contain the sparkle overlay — it's
a CSS layer over the HTML5 player only. To bake the pop-in into the
file, the mux step in `lib/tools/mux-voice-over.ts` would need a
`drawtext` + `fade=in` overlay on the last few seconds, ideally with
a rendered title card PNG produced server-side. Out of scope here.

Pattern is reusable: same `.md-overlay-timed` / `.md-overlay-popped`
classes can power other holiday overlays once their gradient colors
and JSX wrappers are themed.
