## Summary

Salvaged the genuinely additive work from `origin/codex/raj-3`
(Rodolfo's branch, commit `b6bdd28`) into main while keeping every
fix already on main. The branch was named "Fix ffmpeg-static lookup"
in its commit subject but actually shipped a full email-send feature
plus several UX touches in 1195 insertions.

What landed on main:

- **`/api/email/send`** — Resend-backed POST route. Validates `to`,
  `message`, `videoUrl`. Returns 503 with a clean config message if
  `RESEND_API_KEY` is missing (no silent successes). `maxDuration=60`
  per our standing rule. Sender resolution prefers
  `BIRTHDAYBOT_EMAIL_FROM`, falls back to `EMAIL_FROM`, then to
  Resend's onboarding default.
- **`lib/email-template.ts`** — XSS-safe inline-playable HTML email
  with watch-link fallback for inboxes that block video playback,
  plus a plain-text variant.
- **Types**: `EmailSendRequest` + `EmailSendResponse` in `lib/types.ts`.
- **Client**: `studioApi.sendEmail(input)` in `lib/client-api.ts`,
  reusing the existing `parseJson` so the user sees real status-coded
  errors.
- **Email send card** inside StepPreview's sidebar. Renders only when
  `delivery === "email"` (gated by the existing Sends-on segmented
  control). Recipient email input, Send button disabled until
  `generation.videoUrl` exists, inline success/error message.
- **`GeneratedVideo`** wrapper component (new in `app/page.tsx`).
  Keeps an external `voiceOverUrl` `<audio>` element synced with the
  muxed `<video>` via play/pause/seek/ratechange listeners. Only
  matters when ffmpeg muxing failed and the server returns the
  voice-over separately — but the wrapper is harmless when
  `voiceOverUrl` is undefined.
- **Wizard sessionStorage persistence**. Snapshot of `draft`,
  `briefPlan`, `briefCaption`, `briefRequestId`, `briefDraft`, and
  `generation` written under `birthdaybot:wizard-state` with a 2-hour
  TTL. Hydrates on mount; persists on every meaningful state change;
  swallows quota errors silently. Reload mid-flow now resumes
  cleanly. Photo data URL stays under our 3 MB compression cap so
  it fits easily.
- **ffmpeg-static lookup hardening** in `lib/tools/mux-voice-over.ts`:
  direct `import ffmpegStaticPath from "ffmpeg-static"` (Next 15
  bundle-tracing friendly) plus a fallback to the traced
  `node_modules/ffmpeg-static/ffmpeg` path under `process.cwd()` if
  the import doesn't resolve to a usable string. Replaces the prior
  `createRequire` pattern. Should be friendlier to Vercel's tracing
  in cold starts.
- **README** documents `RESEND_API_KEY` and `BIRTHDAYBOT_EMAIL_FROM`.
- **Tests**: new `tests/email-template.test.ts` with 3 cases (inline
  video markup, attribute escaping, watch-not-download copy).
  `tests/creation-form.test.tsx` mock extended with `sendEmail`.

## What we explicitly did NOT take from raj-3

- The 4-step wizard refactor (Who/Photo/Prompt/Email). Would have
  meant losing main's chip palette + suggest-from-photo + Brief
  stage. User direction was clear: keep the 5-step flow.
- `public/demo.mp4` swap (8.5 MB → 29 MB). Asset bloat with no
  user-visible benefit on our flow.

## Blockers Or Risks

- Vercel env: `RESEND_API_KEY` is now configured in production (user
  confirmed mid-merge). With it set, real emails will go out the
  moment the deploy lands. If the user later wants to disable real
  sending without removing the env var, we'd need a feature flag.
- The `BIRTHDAYBOT_EMAIL_FROM` sender must be a verified domain in
  the Resend account. Default falls back to Resend's `onboarding@
  resend.dev`, which works for testing but isn't a great long-term
  default.
- The new ffmpeg-static direct-import pattern depends on
  `ffmpeg-static` exporting a default that resolves to a string at
  build time. Our `next.config.ts` has the binary in
  `outputFileTracingIncludes` for `/api/generate` and
  `/api/jobs/check`, so the fallback path also works on Vercel.
  Worth watching the first cold start to confirm.
- Wizard sessionStorage persistence is per-tab. Cross-tab continuity
  still requires localStorage (which we use for voice setup only).
  Acceptable for the wizard since users typically don't tab-hop
  mid-flow.
