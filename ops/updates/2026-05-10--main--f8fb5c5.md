# Ops Update

- Date: 2026-05-10
- Branch: main
- Commit: f8fb5c5

## Summary

Generalize the fal-error-body surface helper so it applies on the
initial `/api/generate` path, not just the `/api/jobs/check` polling
path.

Trigger: user updated the fal key in production, hit a 403 from fal
on `Make my Mother's Day video`, and the UI showed just "Forbidden".
The actual cause was `User is locked. Reason: Exhausted balance. Top
up your balance at fal.ai/dashboard/billing.` — that string was in
`error.body.detail` but never reached the user because
`/api/generate` was falling back to `err.message` (which the fal SDK
sets to the bare HTTP `statusText`).

Refactor:
- Extracted `providerFailureMessage` + `formatApiErrorBody` from
  `lib/tools/check-video-generation.ts` into `lib/provider-error.ts`.
- `lib/tools/check-video-generation.ts` now imports from the shared
  module (no behavior change there).
- `app/api/generate/route.ts` swapped `err.message` for
  `providerFailureMessage(err)` so any fal/OpenAI/ElevenLabs body
  detail (FastAPI/Pydantic `detail: string`, `[{loc, msg, type}]`
  array, or generic `message`/`error`) surfaces to the UI.

## Blockers Or Risks

- Action still on the user: fal account balance is exhausted. Top up
  at fal.ai/dashboard/billing. No code change can fix that — the new
  surface just makes the cause readable so it isn't a black-box
  "Forbidden".

## Next Context

If we add another provider integration in the future (Suno, Runway,
etc.), use `providerFailureMessage` from `lib/provider-error.ts` in
its route's catch handler. Don't write a new error-message extractor.
