## Summary

Investigated "voice clone fails after a while". Diagnosed against the live
ElevenLabs account, then fixed two latent defects that reproduce the same
symptom independently of the plan.

Root cause of the reported outage was **not credits** — character usage was
334/10,000 (3%). The account had lapsed to the free tier, which hard-blocks
the three things this app depends on. Reproduced directly:

- `POST /v1/voices/add` -> 400 `can_not_use_instant_voice_cloning`
- TTS against an existing clone -> 401 `ivc_not_permitted`
- S2S targeting an existing clone -> 401 `ivc_not_permitted` (no back door)
- Stock fallback voice Rachel `21m00Tcm4TlvDq8ikWAM` -> 402 "Free users
  cannot use library voices via the API", so the safety net was dead too
- `POST /v1/music` -> 402 `limited_access`

fal and OpenAI were healthy throughout (both 200). Last successful clone was
2026-05-10 19:45 UTC, decoded from the orphaned clone names.

The account has since been upgraded to **starter**; IVC, library voices and
the Music API were all re-verified as 200 afterwards.

Code changes:

- `deleteElevenLabsVoice` was dead code — defined, never called. Every fresh
  session minted a clone that was never reclaimed (4 orphans had accumulated
  against a free-tier limit of 3). Now reclaimed lazily: on a voice-limit
  error we delete our own stale clones and retry once. Scoped to the app's
  own name prefix plus `category: "cloned"`, so user-owned library voices can
  never be deleted. Dry-run against the live list: 4 app clones identified,
  22 other voices untouched.
- A cached `providerVoiceId` could outlive the clone it referenced, silently
  degrading every later generation to a stock narrator. Now re-mints from the
  retained sample and retries once. Detection narrowed to 404
  `voice_not_found` so a plan lapse (401) does not trigger a futile re-clone.
- `app/page.tsx` no longer renders a voice-over fallback as a hard generation
  error; it is a `notice` on a delivered video, so it stops displacing the
  success message.

## Blockers Or Risks

- Reclaim keeps the newest 2 app clones. Concurrent generations racing to
  mint beyond that window could have a clone reclaimed mid-flight; the
  self-heal path covers it, at the cost of one extra clone.
- `isVoiceLimitError` matches on provider error text (`voice_limit` /
  "maximum amount of custom voices"). If ElevenLabs reword it, reclaim stops
  firing and behaviour reverts to today's stock fallback — fails safe, but
  silently.
- Unrelated and still open: `components/creation-form.tsx` is imported only
  by tests. The live UI is `app/page.tsx`, which hardcodes `voiceMode:
  "narrate"` and never sets `userMessageDataUrl`. The "Record yourself"
  (speak-yourself) mode is therefore unreachable in the shipped app despite
  full server-side support in `create-voice-over.ts`.
- `.env.example:67` still suggests `ELEVENLABS_STOCK_VOICE_ID=21m00Tcm4TlvDq8ikWAM`
  (Rachel). Fine on a paid plan, but that is exactly the voice that 402s on
  free, so the documented default is a trap if the plan ever lapses again.
