# Ops Update

- Date: 2026-05-10
- Branch: main
- Commit: 9903e76

## Summary

Stop fighting the Preview-step layout — match Brief's single-column
pattern. After two prior fixes (c3ef602, ac88899) that layered
defensive CSS onto a fragile foundation, the postcard was still
rendering at 0 size and the page still had horizontal scroll. The
root issue was the 2-column grid in a widened 1100 px panel hosting
an aspect-ratio'd postcard. Every fix patched one corner; another
broke.

Brief step works because it's the simplest possible thing: 720 px
single-column panel, vertical Field stack. The Preview step now
uses the same pattern.

### Three CSS changes in `app/globals.css`

1. Deleted `.bb-step-panel:has(.bb-preview-layout) { max-width: 1100px }`.
   Preview now uses the default 720 px panel like every other step.
2. Replaced `.bb-preview-layout` grid with `display: flex;
   flex-direction: column; gap: 22px`. Postcard on top, sidebar
   cards stacked below.
3. Replaced `.bb-postcard.is-preview` max-height clamp with the
   canonical webapp pattern: `width: 100%; max-width: 480px;
   margin: 0 auto`. Aspect-ratio: 4/5 inherited from `.bb-postcard`
   derives height automatically. 480 px is the same cap Instagram
   and Vimeo use for portrait media tiles.

### Why this is the right answer

Width-driven sizing is THE pattern when aspect-ratio is involved:

- Set `width: 100%` so the container fills its track.
- Set `max-width: <design cap>` so it stops growing.
- Let `aspect-ratio` derive height from the resolved width.
- Center via `margin: 0 auto`.

Setting BOTH a width source AND `max-height` creates a "fight" —
aspect-ratio tries to derive width from height while the browser
tries to derive height from width. Some viewports resolve to 0
because the constraints become unsatisfiable. That's what we were
hitting.

Sources: MDN aspect-ratio guide, web.dev "Aspect ratio in CSS",
Smashing Magazine fluid media patterns. None of them recommend
`max-height` clamping when aspect-ratio is in play.

### Side benefits

- Sidebar cards (Voice / Sends-on / Recipe / Generate / Email)
  now have full panel width to use, so the Send card recipient
  email input + button no longer get squished or cut off.
- The 880 px breakpoint reflow is gone — single-column already
  works at any width.
- Sidebar button overflow guards are gone — full-width buttons
  in a single column don't overflow.

## Blockers Or Risks

- Visually, Preview now feels more "vertical" than the prior
  side-by-side. That's intentional — it matches Brief and is the
  same shape every other step uses. If we want a side-by-side
  layout back, the right time to revisit is once the user has
  scrolled through a real generation a few times and decided
  they actually miss it.
- The 480 px postcard cap means on viewports above ~720 px the
  postcard will not stretch wider. That's correct behavior for
  a portrait 4:5 tile — stretching it would distort the photo.
