- Date: 2026-05-10

## Summary

Restored the full creation flow inside the new dashboard shell. The codex/merge-raj merge dropped a slick dashboard UI on top of main's backend, but its 4-step Wizard component was hardcoded around a simplified Friend model and skipped: voice mode selector, song style chips, voice-recording (3-tone calibration), speak-yourself recording, editable plan brief, editable birthday message with word counter, granular 3-checkbox consent, voice quality warnings, live progress log, and the AI-generated badge.

The fix renders `<CreationForm />` (which still exists in `components/creation-form.tsx`, fully wired) inside the dashboard's `+ New birthday` entry point via a new `<FullCreationView />` wrapper. The pre-merge creation-form CSS (~1250 lines) was appended back to `app/globals.css` so the legacy classes (`.voice-recorder`, `.voice-mode-card`, `.editable-plan-card`, `.song-style-chip`, etc.) render properly. A small bridge block neutralizes the legacy `.app-shell` height/padding so it sits inside the dashboard's stage instead of taking the whole viewport. The new `bb-*` design system still drives the dashboard chrome.

## Blockers Or Risks

- The old Wizard / StepWho / StepPhoto / StepMessage / StepPreview components remain in `app/page.tsx` but are no longer rendered. Dead code that's worth re-evaluating later: either re-enable as an alternate streamlined entry point, or delete.
- Two separate styling systems now coexist in `globals.css` (the new `bb-*` design tokens + the legacy `.creation-form` aesthetic). Any future visual rework needs to consolidate them.
- The voice-clone setup state in the new dashboard's sidebar (`voiceClone` / `setVoiceClone`) is now decoupled from the actual voice cloning that happens inside `<CreationForm />`. The sidebar's voice-status indicator may show stale info; worth reconciling next pass.
