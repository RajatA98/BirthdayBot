## Summary

Add `.env.example` as the committed source of truth for environment
config; shorten the README env section to a `cp .env.example .env`
pointer plus a category summary.

Drift fixes along the way:
- README listed `OPENAI_CAPTION_MODEL` which is no longer read by
  code (the caption is part of the structured plan call now).
- README's `ELEVENLABS_TTS_MODEL` default was `eleven_multilingual_v2`;
  actual code default is `eleven_v3`.

`.env.example` is grouped into Required / Model overrides / Cultural
voice slots / Music mode / Observability / Email delivery, with a
comment on every line explaining the effect, fallback behavior, and
where to obtain the credential.

## Blockers Or Risks

- Pre-existing local `.env` is gitignored — confirmed with
  `git check-ignore`. New `.env.example` is NOT ignored. Grep'd the
  template for the known fragments of every real key in the local
  `.env` (FAL, OpenAI, ElevenLabs, Langfuse) — only the public
  `FAL_VIDEO_MODEL` default matched the length-based catch-all, which
  is documentation not a secret.

## Next Context

Anyone fresh-cloning the repo from now on can `cp .env.example .env`,
paste in three keys, and run `npx tsx scripts/api-check.ts` to verify
provider connectivity end to end. Same template covers Vercel's env
configuration too — the var names match what's set on the production
tier.

If we add a new env var in the future: add it to `.env.example` in the
same commit so the template doesn't drift again.
