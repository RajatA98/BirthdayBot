# Ops Update

- Date: 2026-05-10
- Branch: main
- Commit: 8773150

## Summary

Fix subject-replacement / hallucination issue where fal/Kling
generated anonymous athletes when the prompt mentioned a triathlon,
losing the source-photo people entirely. User showed a frame: two
runners crossing a finish line — neither was the person from the
uploaded photo.

### Root cause

The previous IDENTITY LOCK directive in `lib/tools/build-video-input.ts`
was strong on "don't replace the subjects" but weak on three things
that turned out to matter for Kling specifically:

1. It didn't explicitly anchor the FIRST frame to the source photo
   ("animate forward from that exact frame").
2. It didn't render `plan.identityAnchors` as a labeled cast roster.
   The anchors only reached the prompt indirectly via
   `plan.keepFromPhoto`, buried late in the joined string.
3. It treated the user prompt as creative-direction-with-a-caveat
   rather than declaring up front that the user prompt describes
   the SCENE, not the cast. When the user wrote "first triathlon",
   the model resolved that as "show triathlon athletes" rather than
   "show the source-photo people in a triathlon-themed scene."

### Fix

Three coordinated changes inside `buildFalPrompt`:

- **FIRST FRAME ANCHOR** (new): "Begin with the uploaded source
  photo as frame 0; animate from that exact frame. The same faces,
  hair, skin tone, body types, outfits, and relative positions
  persist across every subsequent frame."
- **ON-SCREEN CAST** (new): renders `plan.identityAnchors` as
  numbered roster and explicitly bounds it: "These N people are the
  only characters in any frame — never replaced, never joined by
  extras, never swapped during transitions or wide shots."
- **IDENTITY LOCK** rewritten with the load-bearing line: "The user
  prompt below describes the SCENE around them, not a different
  cast — the cast does NOT change to match the prompt; the scene
  adapts around the cast."

Negative prompt extended with the specific observed failure modes:
`anonymous athletes`, `anonymous runners`, `generic triathletes`,
`generic crowd`, `faceless people`, `back of head only of new
people`.

To stay under the 2400-char fal cap (the new directives added
~600 chars), compressed redundant lines elsewhere — removed the
duplicate "Keep the people recognizable" reminder and shortened
the birthday-celebration sentence. Net prompt length back below
the cap with realistic user prompts.

### Tests

- `tests/video-service.test.ts buildFalPrompt` asserts the new
  IDENTITY LOCK + ON-SCREEN CAST blocks and the new "Treat the user
  video prompt as creative scene direction" phrasing.
- `tests/email-template.test.ts` updated for the download-CTA copy

52/52 tests pass; build clean.

## Blockers Or Risks

- This is a prompt-engineering fix; no guarantees in adversarial
  cases. If the user writes a prompt that semantically demands a
  different cast (e.g. "show a stadium of fans cheering"), Kling
  may still drift. Auto-retry runs with safer prompt that drops the
  user prompt entirely — which is a better fallback now that the
  base prompt anchors identity harder.
- Compressed sentences may read marginally less polished in the
  prompt, but they're internal-only — never user-facing.
- The ON-SCREEN CAST block depends on `plan.identityAnchors` being
  populated. The plan-birthday-video prompt requires identityAnchors
  echo photoAnalysis verbatim, so this is reliable. If for some
  reason identityAnchors is empty (unlikely), the cast block is
  omitted and IDENTITY LOCK still fires.
