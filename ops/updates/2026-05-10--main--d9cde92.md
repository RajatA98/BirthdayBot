## Summary

Rebuilt the dashboard wizard so the codex/merge-raj chrome reaches the full
backend instead of the hardcoded Message + style-chip flow. The wizard now
has 5 steps:

1. Who — name & date (unchanged)
2. Photo — upload (unchanged)
3. Prompt — free-form prompt textarea + voice setup. The voice setup card
   from the legacy flow lives here. If a voice clone is already saved
   (localStorage `birthdaybot:new-ui-voice-setup`), we render a "voice
   ready" confirmation with a re-record button instead of the recorder.
4. Brief — new step. Calls `/api/plan` on entry with a simple-mode
   DraftRequest, then renders the director's brief (title, concept, vibe,
   scene direction, motion direction, surprise factor, keep-from-photo,
   birthday message) as editable inputs. Identity guardrails (subjectCount,
   identityAnchors, sceneGuardrails) stay read-only since they're what
   stops the model from swapping out the people in the video.
5. Preview — voice setup card removed from the sidebar (now lives in
   step 3). Replaced with a status card surfacing stock-vs-cloned
   narration. Generate is no longer gated on voice setup; stock-narrator
   path runs end-to-end without recording.

Caching:
- Voice clone state hydrates from localStorage on mount (existing
  behavior at `app/page.tsx:198`). When a generation produces a
  `providerVoiceId`, we save it back so the next generation skips IVC.
- Voice samples already persist via `birthdaybot:voice-draft` in the
  VoiceSetupCard component. No change needed there.
- No DB yet — everything is localStorage + in-memory cache. Worth
  revisiting once we add accounts.

Files changed:
- `app/globals.css` — removed the 1671-line legacy creation-form CSS
  block that the previous reskin attempt had appended. The wizard
  uses the bb-* design system natively now, so we don't need the
  legacy aesthetic to coexist.
- `app/page.tsx` — wizard rebuild: replaced StepMessage with StepPrompt,
  added StepBrief, added `buildSimpleDraftRequest` helper, rewrote
  `generateVideo` to use brief state instead of building a fresh plan
  on each click, updated the footer step counter and Next-button gating.

## Blockers Or Risks

- Voice setup still uses the existing VoiceSetupCard (legacy 3-tone
  calibration). Its CSS classes (`.voice-recorder`, `.voice-mode-card`,
  etc.) are no longer in globals.css — they were appended by the prior
  reskin commit and are now removed. Confirm visually; if the recorder
  looks unstyled, we'll need to scope a small block or refactor the
  card to use bb-* classes.
- StepBrief is editable but doesn't yet allow re-running `/api/plan`
  with edits (no "regenerate brief" button). Edits go directly into
  the PlanRecord that's POSTed to `/api/generate`. That's intentional
  for now — it matches the old flow's behavior — but worth noting.
- The dashboard's existing Friend model still has `style` ("sing-along",
  etc.) and `delivery` fields that we keep populated for postcard
  rendering. They're no longer surfaced in the wizard but the existing
  postcard CSS depends on them. Don't remove without auditing the
  cards on the dashboard.
