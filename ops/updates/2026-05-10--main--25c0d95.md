## Summary

Two user-reported issues bundled because they were called out
together and the diff is small.

### 1. +New Birthday now starts from a clean slate

The wizard's sessionStorage persistence shipped in 51d555a was
overzealous: on every Wizard mount it hydrated `draft`, `briefPlan`,
`briefCaption`, `briefRequestId`, `briefDraft`, `generation` from
`sessionStorage["birthdaybot:wizard-state"]` regardless of how the
wizard was entered. So clicking "+ New birthday" on the dashboard
brought back the previous in-flight session — photo, prompt, brief,
generation progress and all.

Fix in `app/page.tsx`:

- New `clearWizardSnapshot()` helper.
- Called at every fresh-intent entry point: hero "+ New birthday"
  button, `NudgeCard`, dashboard postcard "Edit video", detail-view
  onEdit handler.
- Wizard still hydrates from sessionStorage on a cold reload
  mid-flow (resume polling after refresh). Only fresh-intent clicks
  wipe it.

### 2. Loud failure when fal returns no request_id

When `fal.queue.submit()` returned a response missing or empty
`request_id`, the JobRecord had `providerRequestId: undefined`. The
polling loop in `lib/tools/check-video-generation.ts:49` guards on
`if (apiKey && providerRequestId && providerEndpoint)` — that
condition silently skipped the fal status check, fell through to
the catch-all branch at line 150, and returned `failed` with the
message "Video generation is not configured" + "FAL_KEY is required"
— even when the key was set fine in production.

Fix in two files:

- **`lib/tools/start-video-generation.ts`** — validate
  `result.request_id` is a non-empty string immediately after
  `fal.queue.submit`. If missing/blank, throw with the safe-stringified
  submit response so we can see what fal actually returned. The
  `/api/generate` route's catch surfaces this as a clean
  `stage: "failed"` JobRecord. The auto-retry logic then kicks in
  with a safer prompt.
- **`lib/tools/check-video-generation.ts`** — split the misleading
  fallback. FAL_KEY message ONLY when the key is actually missing;
  otherwise "Video provider didn't return a job id. Auto-retry will
  try again with a safer prompt."

Net: the user no longer sits indefinitely on the spinner when fal
hands back an empty `request_id`. Job fails fast, auto-retry runs,
error message is accurate.

## Blockers Or Risks

- Empty-`request_id` is observed-but-rare. Most generation hangs are
  more likely fal taking long on certain prompts (we cap at 6 min
  client-side: 120 polls × 3s). If hangs persist after this fix,
  longer poll budget or a "still working" UX is the next move.
- The safer-retry path (`safeRetry: true`) drops the user prompt.
  If both attempts come back empty, the user sees a failure —
  preferable to a stuck spinner.
