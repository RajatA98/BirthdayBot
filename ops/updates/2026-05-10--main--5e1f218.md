## Summary

Fixed the Preview step layout slipping off the right edge on wide
viewports.

The wizard step panel `.bb-step-panel` is `max-width: 720px` — right for
single-column steps (Who, Photo, Prompt, Brief), but the Preview step
adds a 2-column grid (`.bb-preview-layout`) where the postcard sits
left and a sidebar (Voice / Sends-on / Recipe / Generate) sits right.
Inside 720 px the sidebar's intrinsic content (the long voice card
description plus the Text/Email/Link segmented buttons) was forcing
the right grid track to push past the panel boundary, which made the
heading and the layout look right-shifted on a 1440 px+ viewport.

Two scoped CSS changes in `app/globals.css`:

- `.bb-step-panel:has(.bb-preview-layout)` widens the panel to 1100 px
  for the Preview step only. Other steps still use 720 px.
- `.bb-preview-layout` columns now `minmax(0, 1fr) minmax(280px, 360px)`
  with a 28 px gap. The sidebar can never exceed 360 px, the postcard
  takes the slack, and the whole thing centers via the panel's
  existing `margin: 0 auto`.

`:has()` is supported across Chrome 105+, Safari 15.4+, Firefox 121+
— well within evergreen-browser scope. Older engines that don't
support it silently fall back to the 720 px panel; cramped but no
overflow regression.

## Blockers Or Risks

- None functional. Visual on very narrow viewports (<800 px) the
  sidebar drops to its 280 px floor; if that ever feels cramped the
  next iteration would stack to single column under a media query,
  but the user didn't ask for that.
