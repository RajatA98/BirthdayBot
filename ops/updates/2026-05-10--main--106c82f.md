# Ops Update

- Date: 2026-05-10
- Branch: main
- Commit: 106c82f

## Summary

Replaced the email "watch link" fallback with a real download CTA and
exposed the same flow in the studio UI.

- Video Output card now offers a "Download video" button when a video
  is ready. It hits `/api/download?url=...&name=birthday-<name>.mp4`,
  which already proxies fal.ai/fal.media/fal.run hosts with
  `Content-Disposition: attachment`.
- Email send route resolves an absolute base URL from the request
  origin (with `BIRTHDAYBOT_PUBLIC_URL` / `VERCEL_URL` / host fallbacks)
  and builds a `downloadUrl` per send. That URL is passed into the
  email template so the inline-video `<a>` fallback and the prominent
  CTA button both link to the proxy instead of the raw, time-limited
  fal URL.
- Email card subhead updated from "watch-link fallback" to
  "download link fallback" to match the new behavior.
- Added `RESEND_API_KEY` to Vercel production env (was missing —
  caused the "Email is not configured" UI state in production despite
  a working key in `.env`).

## Blockers Or Risks

- The download proxy still fetches from the fal-hosted source URL at
  click-time, so if fal expires the underlying URL the download still
  fails. We should consider persisting the muxed MP4 (e.g., to fal
  storage with a longer-lived URL, or our own bucket) before this is
  truly bulletproof.
- The "from" address still defaults to `BirthdayBot
  <onboarding@resend.dev>`. Resend rate-limits this for non-verified
  senders. Set `BIRTHDAYBOT_EMAIL_FROM` once a domain is verified.

## Next Context

If the email link still 404s in production, the most likely cause is a
stale fal source URL. Look at `app/api/download/route.ts` —
`upstream.ok` returns false on expired fal links, surfacing as a 502.
Either re-generate the video or move toward stored muxed output.
