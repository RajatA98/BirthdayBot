# BirthdayBot Handoff

## Current State

`BirthdayBot` is now a working mobile-first `Next.js` MVP with the full core flow implemented:

1. User uploads one shared photo and enters a prompt
2. The app generates a visible agent plan and birthday caption
3. The user approves generation
4. The app starts an async video job and shows progress states
5. The user receives a result screen with video preview, caption, download, regenerate, and adjust actions

## Stack

- Frontend: `Next.js`
- Backend: `Next.js` Route Handlers
- Planning and caption generation: `OpenAI`
- Video generation: `fal`
- Deployment target: `Vercel`
- Database: none in the MVP

## Important Files

- `app/page.tsx`: app shell
- `components/creation-form.tsx`: main product flow UI
- `app/api/plan/route.ts`: server-side plan generation endpoint
- `app/api/generate/route.ts`: starts generation jobs
- `app/api/jobs/[jobId]/route.ts`: job polling and retry handling
- `lib/plan-service.ts`: `OpenAI` planning and caption logic
- `lib/video-service.ts`: `fal` submission and status logic
- `factory/artifacts/*`: planning, implementation, review, test, and deployment docs

## Real Provider Status

- `OpenAI` smoke-tested successfully with the configured key
- `fal` smoke-tested successfully far enough to accept a real queued generation job and return a real request ID
- real video generation is now running through the browser flow instead of failing at the old `Plan not found` step
- Local browser flow can now be exercised at `http://localhost:3000`

## Known Limitation

- the biggest current product issue is output quality, not job startup: the backend prompt-engineering layer still needs tuning to reduce identity drift and produce better videos consistently
- the current `fal` setup is effectively generating 5-second videos right now; duration selection has not been fully wired through to the provider request yet
- plan/job state is now persisted in a local file-backed store for dev stability, but it is still not a production-grade persistence layer

## What To Do Next

- Run the app locally with `npm run dev`
- Test the real browser flow with real photos
- Tune the backend prompt engineer to better preserve exact subjects and reduce hallucinated people
- Wire explicit `duration`, `aspect_ratio`, and other provider controls through to `fal`
- If the project moves beyond hackathon scope, replace the local file store with proper persistence
